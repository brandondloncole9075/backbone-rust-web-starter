## Overview

Backbone Application gives Rust developers an established base for creating web services with Axum. It starts with a working HTTP server, a health check route, request logging, adjustable CORS support, and the framework crates needed to continue building without first assembling a project structure.

Alongside the web layer, the skeleton includes infrastructure commonly required by backend applications. PostgreSQL pooling, Redis services managed through Docker Compose, framework-managed migrations, and settings loaded from YAML or environment variables are already connected. The result is a structured starting point for extending a service with application-specific functionality.

## Getting Started

First clone the project and move into its directory:

```bash
git clone https://github.com/brandondloncole9075/backbone-rust-web-starter.git
cd backbone-application
```

Make sure the Rust toolchain is installed. Then bring up the local database and cache services:

```bash
docker compose up -d
```

Launch the application through Cargo:

```bash
cargo run
```

After startup, the web server is available on port `8080`.

## Running the Application

To run the service during development:

```bash
cargo run
```

In a separate terminal, call the health route:

```bash
curl http://localhost:8080/health
```

A normal local development sequence is:

1. Bring PostgreSQL and Redis online with Docker Compose.
2. Provide application settings through YAML or the environment.
3. Run migrations whenever database changes need to be applied.
4. Start the Axum service with `cargo run`.
5. Build on the imported Backbone framework crates as the application grows.

To produce a release-mode build, use:

```bash
cargo build --release
```

## Application Settings

Runtime options may be defined in a YAML configuration file or passed through environment variables. These settings cover service connection information, CORS options, and other values required while the application is running.

For example:

```dotenv
DATABASE_URL=postgres://user:password@localhost:5432/app
REDIS_URL=redis://localhost:6379
HOST=0.0.0.0
PORT=8080
```

Do not commit passwords or deployment-specific configuration to the repository. If YAML and environment configuration are combined, use the project's established naming and precedence rules.

## Frequently Asked Questions

### What command starts the server?

From the project directory, run `cargo run`. The server is set to listen on port `8080`.

### What does the Docker Compose environment include?

The Compose configuration provides PostgreSQL and Redis for local development.

### Where do application settings come from?

Settings can be entered in the supported YAML configuration file or supplied as environment variables. This includes database connection information, service values, and middleware configuration.

### How can I test whether the service is available?

Send a request to the health endpoint:

```bash
curl http://localhost:8080/health
```

### What can cause startup problems?

Check that Rust and Cargo are installed, the Docker-managed services are running, the PostgreSQL and Redis configuration is valid, and port `8080` is not already in use.

### How are migrations run?

Use the migration runner provided by the framework. PostgreSQL connection settings must be configured before migrations are started.

### Where can I find newer versions?

Review the repository for later releases or updates, then refresh the local checkout and rebuild the project with Cargo.
